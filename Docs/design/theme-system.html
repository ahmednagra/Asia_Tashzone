TashZone · theme system v4 · research-backed

Three rooms to play in

A TashZone theme is not a colour list. It is a complete room: the table, the light, the materials, the typography, the way things move and the way they feel under your thumb. Switching theme should feel like walking into a different place, while the cards, the layout and the rules never move.

Status: proposal for approval. No code has been changed. Every colour on this page is checked live against WCAG 2.1 with the same formula as theme/tokens.ts, and against a comfort ceiling for long sessions (see rule 01).

What the research says

Six findings shaped this system. Each one turns into a rule below.

Pure black + pure white hurts on long sessions

White on black is a 21:1 contrast, the harshest a screen can produce. At reading length it causes halation: text seems to bleed into the background. The guidance is a deep tinted ground (not #000) and off-white text (not #FFF), keeping contrast high but not maximal.

Sources: KTC "Why dark mode still causes eye strain"; UXPin "Dark mode benefits 2026"; LifeTips OLED eye-strain

Dark-first is now the default, not the variant

Over 80% of Android users run dark mode. Card games are played in the evening, in bed, on the bus. All three TashZone themes are dark; light mode is deliberately retired.

Sources: UXPin; Envato "Colour scheme trends 2026"

Green felt exists to reduce visual tension

Card tables have been green since 18th-century British gaming rooms because green calms and lets the eye rest between cards. Casinos keep it for exactly that reason. Blue and red felts are used to mark variety and "high-stakes" rooms.

Sources: Casino.org; Borgata; LatestCasinoOffers

Cards outrank chrome

Marvel Snap's rule: the cards always win the visual hierarchy, and the UI exists to point at them. Its chrome is dark "piano glass" so the art pops. Hearthstone, Slay the Spire and Balatro all win on clarity: consistent icons, keywords and instant tooltips.

Sources: Tiffany Smart (Snap UI); Sunstrike "Best card games 2026"

Colour as the label (the Balatro pattern)

The most-copied card look right now: dark felt with drifting colour bands, chunky outlined slabs, and a strict colour code where blue = chips (#009DFF), red = mult (#FE5F55), gold = money. Players read value without reading text. Every colour cue and pulse exists to show a number changing.

Sources: Blake Crosley "Juicy feedback in Balatro"; Balatro wiki; halabaojia art breakdown

The home audience expects maroon, gold and festival

Teen Patti and Callbreak apps dominate South Asia and have converged on maroon-and-gold luxury; the newest ones now ship dark mode and colour themes. For authenticity, Sindhi Ajrak gives a real regional palette: deep indigo, madder crimson, white and black.

Sources: ENV Media on Teen Patti; Coherent Lab guide 2026; Kalantir & Wikipedia on Ajrak

Ten rules every theme obeys

These are enforced by tests, not taste. A theme that breaks one cannot ship.

Comfort ceiling.

Body text sits between 7:1 and 18:1 on its surface. Below 7 is hard to read; above 18 causes halation on long sessions. No theme uses #000000 ground or #FFFFFF text.

Tinted grounds.

Every background carries the theme's hue (green, madder, navy). A neutral grey ground is what made the old Dark theme feel like nothing.

The table is a calm zone.

Felt colour is chosen for rest, not excitement. All "on table" text stays ≥ 4.5:1 on every felt. Ornament never crosses the play area.

Cards never change.

Card faces (#FBF8F1), suit colours, the four-colour deck and legal-move halo are identical in all themes. Only the card back is themed. This keeps muscle memory and accessibility stable.

Colour is a label.

Three value tokens exist in every theme: points, bid, coins. A theme may tune their hue, never their meaning.

One accent, one job.

The accent marks "current" and "selected" only: active tab, chosen chip, your turn. It is never used for body text.

Type is part of the theme.

Each theme owns a display face, a casing rule and a numeral style. The body face stays Jost for legibility; Nastaliq stays for Urdu.

Shape and material are part of the theme.

Corner radius, surface treatment (glass / framed / slab) and button construction change per theme. This is where most of the "different room" feeling comes from.

Motion has a budget.

Each theme declares a motion profile. reducedMotion collapses every profile to 120 ms fades. Nothing loops forever on the table in any theme.

Touch and text floors.

44 dp targets, 13 pt minimum text, 4.5:1 minimum contrast, 3:1 for borders and icons, in every theme, on every screen.

The three themes

Same home screen, three rooms. The token table under each phone is computed live.

Spec matrix

Every row is one field in the theme spec. Components read these fields; screens never hard-code them.

Motion, haptics and sound profiles

Feel is half of a theme. These profiles map straight onto the existing motion tokens, hapticStrength and the sound helper.

Reduced motion (user setting or OS setting) forces every theme to: deals and plays as 120 ms fades, no shake, no breathing, no confetti, count-ups become instant. Haptics stay, sound stays.

The switch moment

Changing theme should be an event, not a re-render. It is also the best "wow" in the settings screen.

1 · Live preview, real components

The picker shows a miniature of the actual table (felt, rim, card back, HUD) and the actual primary button, rendered by the same components. No hand-painted preview that drifts from reality.

2 · Re-dye transition (≈ 480 ms)

The new felt colour sweeps across the screen from the tapped option, like dye spreading through cloth, followed by the surfaces snapping to the new material. One haptic tick at the end. Under reduced motion: a 120 ms cross-fade.

3 · Signature sound

Mehfil: a soft tabla tap. Darbar: a short brass chime. Arcade: an arcade "blip". Played once on switch, and reused as the theme's turn-start cue so the sound world matches the room.

4 · Remembered per device, previewable per game

The choice persists (existing tashzone.theme.v1 key). The table menu gets a "Try another room" shortcut so players discover themes where it matters most.

How to build it

  • Replace SemanticColors-only themes with a ThemeSpec (below). useTheme() returns the whole spec; c stays for backward compatibility.
  • Storage IDs: emerald (Mehfil), gold (Darbar), arcade. Saved dark or light map to emerald. One picker only; delete the System/Light/Dark picker.
  • Delete every name === "dark" branch (13 places) and read spec.surface, spec.button, spec.ornament instead. StatusBar is always light.
  • Six components carry 90% of the change: Screen (ground + vignette), GlassCard (surface style), GoldButton (button style), TabBar, Felt (felt, rim, bands, card back) and Header (display type). Screens should need no edits.
  • Two decided details. Darbar's card back is a true Ajrak (indigo field, madder medallions, white resist lines, brass border): authentic four-colour Ajrak, symmetric as card backs must be, and it repeats the felt's madder so it belongs on the table. Arcade's button is deep red #C8372A with white text (WCAG 5.2:1, APCA Lc 80); the bright coral #FF5E4D stays the bid value colour and the button's top highlight. White on bright coral passes APCA (Lc 61) but fails WCAG (3.0:1); dark ink on it passes WCAG (6.5:1) but reads weaker in APCA (Lc 48). Darkening the fill is the only option that passes both.
  • Fonts: register Jost 700 and Bodoni Moda 700 under their own family names; stop faking weights with fontWeight.
  • Tests: loop contrast.test.ts over all three specs, add the 18:1 comfort ceiling, and check points/bid/coins on bg, surface and felt.
  • Wire the dead settings this unlocks: reducedMotion, hapticStrength, sfxVolume now have consumers via the profiles.
  • Splash and navigation: splash background becomes Mehfil ground; Stack/Tabs get contentStyle from spec.c.bg; first render waits for theme + profile + fonts.
// theme/tokens.ts — the theme pattern
export type ThemeId = "emerald" | "gold" | "arcade";

export interface ThemeSpec {
  id: ThemeId;
  name: { en: string; ur: string };                      // "Mehfil" / "محفل"
  c: SemanticColors;                                      // bg, surface, surfaceRaised, text…, borders
  accent: { color: string; on: string };                  // selected / current only
  value: { points: string; bid: string; coins: string };  // colour = label
  felt: { base: string; lit: string; deep: string; rim: RimStyle; bands?: string[] };
  cardBack: "weave" | "ajrak" | "stripe";
  type: { display: string; titleCase: "none" | "uppercase"; tracking: number; numerals: string };
  shape: { radius: number; chip: number; felt: number; button: number };
  surface: "glass" | "framed" | "slab";
  button: "gradient" | "embossed" | "slab";
  ornament: "vignette" | "rule" | "bands";
  motion: "lush" | "standard" | "juicy";                  // collapses to "fade" under reducedMotion
  haptic: { play: HapticStrength; win: HapticStrength };
  sound: { switch: string; turn: string; win: string };
}
